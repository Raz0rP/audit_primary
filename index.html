Basse

L'audit couvre les 28 écrans principaux et les composants partagés (bento + app/lib/widgets). Il s'appuie sur une lecture statique du code, croisée avec les tokens de design Bento.

À traiter en priorité : les 6 issues critiques bloquent des utilisateurs sur des flux essentiels (connexion, messagerie, rendez-vous). Les 7 issues hautes touchent tous les utilisateurs — notamment ceux qui agrandissent le texte sur leur téléphone, qui sont beaucoup plus nombreux que les utilisateurs de lecteur d'écran.

Contrastes couleurs

Le ratio de contraste mesure la différence de luminosité entre un texte et son fond. En dessous de 4.5:1, le texte devient difficile à lire pour des personnes malvoyantes, âgées, ou dans de mauvaises conditions d'éclairage (soleil, écran bas). Le seuil WCAG AA est 4.5:1 pour le texte courant, 3:1 pour les grands titres et les icônes.

TexteFondRatioRésultatUtilisations
#3A1C33 prune #EFC712 jaune 8.5:1 ✓ Excellent Bouton principal (fond clair)
#ffffff blanc #3A1C33 prune 13.8:1 ✓ Excellent Bouton principal (fond sombre)
#646464 gris foncé #ffffff blanc 6.4:1 ✓ OK Textes secondaires sur fond blanc
#8C8C8C gris moyen #ffffff blanc 3.4:1 ✗ Insuffisant Initiales avatar, boutons désactivés, placeholders
#8C8C8C gris moyen #F5F5F5 gris clair 3.0:1 ✗ Insuffisant Initiales avatar sur fond gris
#FF5A5A rouge erreur #ffffff blanc 3.1:1 ✗ Insuffisant Messages d'erreur, indicateurs d'état
#22AF5C vert succès #ffffff blanc 2.7:1 ✗ Insuffisant Indicateurs de validation, bilans

Les couleurs erreur et succès sont toujours accompagnées de texte — le critère « ne pas communiquer par la couleur seule » est respecté. Mais le texte lui-même n'est pas lisible pour quelqu'un de malvoyant si le ratio est sous 4.5:1.

  data: MediaQuery.of(context).copyWith(textScaleFactor: 1.0),
  child: child,

Méthodologie & Prochaines étapes

Sources : Audit par lecture statique du code source Flutter. Critères : WCAG 2.1 niveau AA, RGAA 4.1 adapté au mobile natif, Apple HIG Accessibility, Material Design Accessibility. Les composants tiers et le mode sombre n'ont pas été testés dynamiquement.

Limites : Cet audit ne remplace pas un test avec de vrais utilisateurs en situation de handicap, ni un test manuel sur appareil. Il identifie les risques — un test terrain confirmera les priorités.

Plan d'action recommandé

  1. Sprint 1 — Critique (A1–A6) · Corrections ciblées dans les composants partagés et les écrans login / messagerie / documents. Estimé : 3–5 jours dev.
  2. Sprint 2 — Haute (B1–B7) · Tokens couleur, Bento TextField, BottomSheet, vérification agrandissement texte. Estimé : 3–4 jours dev + 1 jour design.
  3. Test sur appareil · Session de test avec VoiceOver (iOS) et TalkBack (Android) — idéalement avec un utilisateur en situation de handicap.
  4. Sprint 3 — Moyenne (C1–C11) · Animations, zones tactiles, mode sombre, messages d'erreur. Estimé : 3–4 jours.
  5. Basse (D1–D4) · À traiter en opportunité lors du passage dans les fichiers concernés.
